# Socrates 后端系统产品报告

**2026 年 5 月 · v1.0**

---

## 产品概述

Socrates 是一个面向高中生的 AI 数学辅导系统。学生输入题目和自己的作答过程，系统能够：**自动判断对错 → 找出具体错误 → 定位卡住的位置 → 根据认知特征给出分层提示 → 更新学习画像 → 推荐下一道合适的练习题**。

六大业务模块全部完成并可运行，394 个自动化测试通过，26 个 API 端点可用，知识库覆盖高中数学全部 12 章、175 个知识点。

---

## 一、产品核心能力

### 能力 1：自动批改学生作答——不只是对答案

**做什么**：学生提交一道题的解答过程，系统判断答案和推理是否正确，并逐行指出具体的错误类型。

**如何工作**（链式验证）：

系统采用两步法进行评估，而非一次性让大模型判断：

```
第 1 步：系统先不看学生答案，自己独立计算出正确答案
第 2 步：拿着标准答案，逐行对比学生的每一步推理
        → 最终答案一致吗？
        → 每一步的计算对吗？
        → 有没有漏掉关键步骤？（如漏求了一个临界点）
        → 用错定理了吗？（如把"求极值"当成"解方程 f(x)=0"）
        → 代入具体数值验证（如通项公式代入 n=1,2 验证）
```

**与简单对答案的区别**：对答案只告诉你"错了"；本系统告诉你"错在哪里、什么类型、为什么错"。

**实际效果**：用 10 道涵盖集合、函数、三角、数列、向量、解析几何、立体几何、概率、不等式的真实高中题目测试：

| 指标 | 结果 | 说明 |
|------|:--:|------|
| 正确作答识别 | 90% | 学生做对时，系统能正确判断为"对" |
| 错误作答捕获 | 90% | 学生做错时，系统能准确指出具体错误 |
| 误判分析 | — | 唯一短板是纯文本 LLM 在立体几何空间推理上的固有局限 |

具体错误识别示例：

| 学生作答 | 系统判断 | 指出的问题 |
|----------|:--:|------|
| 求 f(x)=x³-12x+5 在 [-3,3] 上最值，只写了 f(2) 和端点 | ❌ 错误 | 遗漏了 x=-2 这个临界点，没有计算 f(-2) |
| 错把"求极值"写成"解方程 f(x)=0" | ❌ 概念错误 | 混淆了"求极值（令 f'=0）"和"求零点（令 f=0）" |
| 数列通项写成 a_n=2n+3，正确答案是 2n+1 | ❌ 计算错误 | 首项代入 n=1 验证：学生得 5，正确得 3 |
| 向量点积计算 a·b=2*(-1)+1*3=1 完全正确 | ✅ 正确 | — |

### 能力 2：不会做时给提示——R 型和 M 型两种维度、九个级别

这是系统最核心的辅导能力。学生解题卡住时，系统不会直接给答案，也不会一刀切地"给个提示"。而是先判断学生属于哪种困难类型，再根据需要的帮助程度给出对应级别的提示。

---

#### 两种困难维度：R 型 vs M 型

系统通过五节点流水线自动判断学生卡住的原因属于哪种维度：

| 维度 | 全称 | 含义 | 典型表现 |
|------|------|------|----------|
| **R 型** | Resource（知识资源型） | 学生**缺知识**——不知道用哪个公式、不知道这个定理怎么用 | "我知道要求极值但忘了怎么求导" |
| **M 型** | Metacognitive（元认知型） | 学生**有知识但不会调用**——知道公式，但不知道现在该用哪个、不知道怎么组织思路 | "我记得求导公式，但接下来该干嘛？" |

**为什么区分 R 和 M 很重要**：

- 对 R 型学生给 M 型提示（如"你想想还有什么方法？"）→ 没用，因为他缺的是知识，不是思路
- 对 M 型学生给 R 型提示（如"用换元法"）→ 治标不治本，他下次换个题还是不知道怎么组织思路

区分维度之后，系统用**维度比例（dimension_ratio）** 追踪学生长期倾向——"这个学生 70% 的时候是因为缺知识卡住的（R 偏），还是 70% 的时候是有知识但不知道用（M 偏）"——从而在后续推荐和策略中做针对性调整。

---

#### 九个提示级别（R1-R4 + M1-M5）

每个维度内，系统提供递进强度。从最低强度开始，学生反馈"还是不会"后才升级。

**R 维度（知识资源型）—— 帮学生补充缺失的知识**：

| 级别 | 递进程度 | 可以做什么 | 不可以做什么 | 示例（题目：求 f(x)=x³-6x²+9x 的极值，学生已求出 f'） |
|------|:--:|------|------|------|
| **R1** | 最低，方向引导 | 从题目条件中挑关键信息，反问学生 | 不提及任何定理名、方法名、公式形式 | "你算出了导数 f'(x)=3x²-12x+9，导数能告诉你关于原函数的什么信息？" |
| **R2** | 低，知识指路 | 指明需要用什么定理/知识，并解释为什么 | 不给出第一步的具体操作形式 | "你已经求了 f'(x)=3x²-12x+9，现在需要找极值点。回忆一下：导数为零的点与极值有什么关系？" |
| **R3** | 中，给出第一步形式 | 给出第一步的理论形式，说明为什么这样操作 | 不代做具体数值计算——让学生自己算 | "令 f'(x)=0，解这个二次方程求出临界点。因为极值只可能出现在导数为零的点。现在解方程 3x²-12x+9=0。" |
| **R4** | 最高，完整步骤 | 给出完整可执行的计算步骤和中间结果 | — | "f'(x)=3x²-12x+9=3(x-1)(x-3)。令 f'(x)=0 得 x=1 或 x=3。x=1 处 f''(1)=-6 为极大值点，极大值为 f(1)=4；x=3 处 f''(3)=6 为极小值点，极小值为 f(3)=0。" |

**M 维度（元认知型）—— 帮学生激活策略思维**：

| 级别 | 递进程度 | 可以做什么 | 不可以做什么 | 示例（同上题目） |
|------|:--:|------|------|------|
| **M1** | 最低，反思引导 | 让学生评估自己已做的步骤是否正确，回想类似的题 | 不指明任何具体方法或知识 | "你已求出了导数，回顾一下：你做的这些步骤在朝着目标前进吗？求极值需要什么条件？" |
| **M2** | 低，方向指引 | 指出一个可行的思考方向，解释为什么可能有效 | 不指定具体方法——让学生自己选 | "你已经求了导，下一步需要分析导数的符号变化来判断单调性。为什么符号变化是关键？" |
| **M3** | 中，策略推荐 | 推荐一个具体的解题策略，解释为什么选它 | — | "你可以用二阶导数判断极值类型。f'(x) 是二次函数，二阶导数 f''(x)=6x-12 可以快速判断凹凸性。这样比符号表更直接。" |
| **M4** | 高，路径对比 | 给出 2-3 种可行方法，比较优劣，让学生选 | — | "判断极值有两种方法：(1)符号表法，画出 f' 的符号变化，直观但步骤多；(2)二阶导数法，计算 f'' 在各临界点的值，快但对三次以上可能不够。本题是三次函数，两种都可行。你倾向哪种？" |
| **M5** | 最高，完整思路 | 给出完整解题逻辑链 + 类比标准题型 | — | "这道题属于'利用导数研究三次函数性质'的标准题型。标准流程：(1)求导 → (2)令导数为零 → (3)用二阶导或符号表判断极值性质 → (4)代入求函数值。类似题如求 f(x)=2x³+3x²-12x 的极值，解法完全相同。" |

**R 与 M 的核心区别总结**：

| | R 型提示 | M 型提示 |
|------|------|------|
| 针对的问题 | "不知道用哪个公式" | "知道公式但不知道现在该干嘛" |
| 提示侧重 | **给知识**（定理名、公式、操作） | **给思路**（策略选择、方向、自我反思） |
| 递进逻辑 | 方向→知识名→第一步形式→完整步骤 | 反思→指方向→推荐策略→对比路径→完整逻辑 |
| 信息密度 | 逐步增加知识细节 | 逐步增加策略框架和元认知引导 |

### 能力 3：追踪学生长期学习画像

系统不只是"这道题做对了吗"，而是持续追踪每次干预，构建学生的**认知特征画像**。

**画像包含什么**：

| 指标 | 含义 | 示例 |
|------|------|------|
| dimension_ratio | R 型断点占比 = 知识缺口型问题的比例 | 0.67 表示 67% 的时候是因为缺知识卡住的 |
| ratio_trend | 这个比例的近期变化趋势 | "rising" = R 型越来越严重 / "falling" = 在改善 / "stable" = 稳定 |
| trend_confidence | 趋势判断的可信度（基于样本量） | 干预 < 5 次时置信度低 |
| 薄弱维度 | 哪些 R/M 级别出现频率最高 | ["RESOURCE_R2", "METACOGNITIVE_M3"] |
| total_interventions | 累计干预次数 | 10 |
| total_solved | 成功解决的次数 | 7 |

**画像如何驱动后续功能**：

| 画像数据 | 驱动什么 | 怎么用 |
|------|------|------|
| dimension_ratio > 0.65（R 偏） | 推荐系统 → SAME_KP 策略 | 继续做同知识点题，补知识缺口 |
| dimension_ratio < 0.35（M 偏） | 推荐系统 → VARIATION 策略 | 换不同方法做同一题型，训练策略调用 |
| dimension_ratio 在 0.35-0.65 | 推荐系统 → BALANCED 策略 | 随机选择薄弱知识点，均衡查漏补缺 |
| ratio_trend = "rising"（R 型加剧） | 教学策略 → 增加讲授比例 | 退回去多讲、少练 |
| ratio_trend = "falling"（在改善） | 教学策略 → 增加练习比例 | 少讲、多练 |
| 干预次数 < 3 | 冷启动 | 用默认画像，积累到 3 次后开始个性化 |

**为什么重要**：没有画像，每个学生看到的都是同一套逻辑。有了画像，推荐和策略随着学生特征动态调整——真正做到了"千人千面"。

### 能力 4：个性化推荐下一题

不是随机抽题，不是题库匹配。而是**基于学生画像 + 知识本体 + LLM 实时生成新题**。

**推荐流程**：

```
1. 读取学生画像 → 知道学生的 dimension_ratio、薄弱知识点
2. 画像驱动锚点选择：
   - R 偏 (>0.65) → SAME_KP 策略：找当前知识点的前置知识，巩固基础
   - M 偏 (<0.35) → VARIATION 策略：找同题型的其他方法，变式练习
   - 均衡 (0.35-0.65) → BALANCED 策略：随机选择薄弱知识点
3. 检索 175 个知识点 + 110 个题型映射 → 确定目标知识点和方法
4. LLM 根据锚点实时生成一道新题（含答案和提示）
5. LLM 不可用时自动降级到 19 道精选备用题库
```

**生成题目示例**：

```
知识点：KP_3_13（函数零点小题策略）
策略：BALANCED
生成题目："已知数列 {a_n} 满足 a_{n+1}=2a_n+3, a_1=1，求 a_5"
答案：61
方法：待定系数法
难度：3/5
```

**推荐策略对比**：

| 策略 | 适用场景 | 目标 | 题目特点 |
|------|------|------|------|
| SAME_KP | R 偏学生 | 巩固基础，补知识缺口 | 当前知识点的前置变体，降低难度 |
| VARIATION | M 偏学生 | 拓宽思路，训练策略调用 | 同一题型换不同解法，排除最近用过的方法 |
| BALANCED | 均衡学生 | 查漏补缺 | 从薄弱知识点中随机选 |

### 能力 5：自适应教学策略

根据学生画像自动输出教学建议——告诉老师或系统对这个学生应该怎么教。

**七种策略矩阵**：

| 策略标签 | 触发条件 | 讲授 | 练习 | 讨论 | 说明 |
|------|------|:--:|:--:|:--:|------|
| R_dominant_worsening | R 偏 (>0.65) + 趋势恶化 | 45% | 40% | 15% | 知识缺口在扩大，需要多讲少讨论 |
| R_dominant | R 偏 + 非恶化 | 35% | 45% | 20% | 以讲带练，先建立知识框架 |
| M_dominant | M 偏 (<0.35) + 非改善 | 20% | 35% | 45% | 策略调用弱，多讨论引导元认知 |
| M_dominant_improving | M 偏 + 趋势改善 | 20% | 40% | 40% | 策略能力在恢复，保持讨论节奏 |
| balanced | 均衡 (0.35-0.65) | 30% | 50% | 20% | 以练习为主，适度讲授 |
| + 新学生调整 | 干预 < 3 次 | +5% | -5% | — | 新学生适当增加引导 |
| + 有经验调整 | 干预 > 10 次 | -5% | +5% | — | 有经验学生增加自主练习 |

策略输出的三个比例直接可作为排课/备课参考。

### 能力 6：前端交互界面

系统配套前端 4 个页面，覆盖完整学习流程。核心设计理念：**将解题→评估→干预→推荐融合为一个连续的学习流**，学生不需要在多个页面间跳转。

| 页面 | 路径 | 功能 | 对接的后端模块 |
|------|------|------|:--:|
| **首页** | `/` | 系统状态统计 + 入口卡片 | 健康检查 |
| **学习** | `/study` | 题目输入 → 自动评估 → 做错给提示 → 做对推荐下一题。一条链完成 | 解题 + 干预 + 推荐 |
| **画像** | `/profile/:id` | R/M 维度比例进度条 + 指标卡 + 路由提示 | 学生画像 |
| **教学** | `/teaching/:id` | 讲授/练习/讨论三色比例条 + 策略标签 | 教学策略 |

**前端与后端模块对应关系**：

```
前端 "学习" 页面 ──────── 后端 解题 + 干预 + 推荐（三个模块协同）
前端 "画像" 页面 ──────── 后端 学生画像
前端 "教学" 页面 ──────── 后端 教学策略
```

设计风格：学术杂志风（Editorial Academic）—— 暖纸白底色、深墨色文字、粉笔蓝强调色、网格纸纹理、衬线标题字体，区别于常规 EdTech 模板。

## 二、完整使用流程（端到端）

以下是一次真实用户交互的完整链路，从学生提交作答到系统输出推荐：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 步骤 1：提交题目和作答                                               │
│   学生 → 系统：题目「求 f(x)=x³-6x²+9x 的极值」，作答「f'=3x²-12x+9,  │
│             令 f'=0 得 x=1, 最大值 f(1)=4」                         │
│   系统 → 学生：❌ 发现错误                                           │
│         · 只求了 x=1，遗漏了 x=3 这个临界点                           │
│         · 未计算 f(3) 的值来比较                                     │
│         · 没有验证 x=1 是极大还是极小                                 │
│         · 置信度 94%                                                │
├─────────────────────────────────────────────────────────────────────┤
│ 步骤 2：断点定位 + 维度判断                                          │
│   系统自动分析：                                                      │
│         · 断点位置：第 2 步（找临界点）—— 解二次方程漏了一个根          │
│         · 维度判断：RESOURCE 型 —— 不是不会组织思路，是漏算了一个根     │
│         · 子类型：R2 —— 学生需要知道"二次方程应该有几个根"             │
├─────────────────────────────────────────────────────────────────────┤
│ 步骤 3：生成提示（R2 级别——知识指路）                                 │
│   系统 → 学生：                                                       │
│         "f'(x)=0 是一个二次方程。回想一下：二次方程通常有几个根？        │
│          你求出的 x=1 是一个，另一个在哪里？"                           │
│                                                                     │
│   同时系统从知识库检索到"二次方程求根公式"相关内容，注入提示背景          │
├─────────────────────────────────────────────────────────────────────┤
│ 步骤 4：学生反馈（假设"有帮助，继续做出来了"）                          │
│   学生 → 系统：反馈"有帮助"                                            │
│   系统 → 学生：确认最终答案是否正确                                     │
│   系统内部：自动更新画像                                               │
│         · 追加干预记录：RESOURCE 型, R2 级, 结果=SOLVED                │
│         · 重算 dimension_ratio                                       │
│         · 重算 ratio_trend                                           │
├─────────────────────────────────────────────────────────────────────┤
│ 步骤 5：推荐下一题                                                    │
│   系统读取更新后的画像 → 选择推荐策略 → 检索知识锚点 → LLM 生成新题      │
│   系统 → 学生：                                                       │
│         "已知函数 f(x)=2x³+3x²-12x，求极值点（用二阶导数法）"           │
│         答案：(极大值点 x=-2，极小值点 x=1)                              │
│         提示：先求一阶导，再求二阶导，注意符号判断                        │
│         策略：SAME_KP（同知识点巩固）                                   │
│         难度：3/5                                                     │
├─────────────────────────────────────────────────────────────────────┤
│ 步骤 6：教学策略（供老师参考）                                         │
│   系统读取画像 → 输出：                                                │
│         策略：R_dominant                                              │
│         比例：讲授 35% / 练习 45% / 讨论 20%                            │
│         说明："知识缺口明显，以讲授+练习为主帮助建立知识框架"               │
└─────────────────────────────────────────────────────────────────────┘
```

|------|:--:|:--:|------|

| 备用题库降级 | 推荐 | ✅ | LLM 不可用时自动切 19 道精选题 |
| 推荐历史追踪 | 推荐 | ✅ | 记录每次推荐，支持反馈 |

| 自适应教学策略 | 策略 | ✅ | 7 种策略 × 3 级经验，输出讲授/练习/讨论比 |
| 事件自动化串联 | 全局 | ✅ | 解题→干预→画像更新→推荐，无需人工介入 |

## 五、核心指标

| 指标 | 数值 | 说明 |
|------|------|------|
| 知识点覆盖 | 175 个 | 高中数学全部 12 章 |
| 题型映射 | 110 种 | 知识点到题型的关联 |

| 教学策略 | 7 种 | 含经验等级适配 |
| 评估准确率 | 90% | 10 题 benchmark，正确识别+错误捕获 |
| 备用题目 | 19 道 | 覆盖 5 难度、10 章 |
| 知识库文档 | 298 篇 | 175 KP + 13 方法 + 110 题型 |
| API 端点 | 26 个 | 全部可用 |
| 测试用例 | 394 个 | 全部通过 |

## 六、技术概要

- Python 3.12 + FastAPI 异步框架
- 阿里云 DashScope Qwen 系列大模型
- MongoDB 持久化（连接失败自动降级内存模式）
- DashScope Embedding API 实现轻量知识检索（零外部向量数据库）
- 143 个 Python 文件，~16,500 行代码
- 394 个 pytest 用例覆盖六模块 + 集成测试

## 七、演示方式

```bash
# 启动
cd backend && uvicorn app.main:app --host 0.0.0.0 --port 8000

# 验证运行
curl http://localhost:8000/api/v1/health

# 演示解题（含学生作答 → 自动批改）
curl -X POST http://localhost:8000/api/v1/solving/reference \
  -H 'Content-Type: application/json' \
  -d '{"problem":"求 f(x)=x^3-6x^2+9x 的极值","student_work":"f'\''(x)=3x^2-12x+9\n令 f'\''=0 得 x=1\n所以极大值为 f(1)=4"}'

# 演示推荐
curl -X POST http://localhost:8000/api/v1/recommendations/recommend \
  -H 'Content-Type: application/json' \
  -d '{"student_id":"demo","trigger":{"outcome":"SOLVED","current_problem_kps":["KP_3_13"],"current_difficulty":2,"session_id":"demo"}}'

# 查看画像
curl http://localhost:8000/api/v1/profile/demo

# 获取教学策略
curl -X POST http://localhost:8000/api/v1/teaching/strategy \
  -H 'Content-Type: application/json' \
  -d '{"student_id":"demo"}'
```

前端页面：`http://localhost:5173`
